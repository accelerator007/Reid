# Security

Current runtime context and release status: [AGENTS.md](AGENTS.md). Prior wording is preserved in [the history archive](docs/history/SECURITY.md).

RLS is deny-by-default. Secrets stay in provider stores. Use signed file URLs, hashed single-use approval tokens, rate limits and Turnstile. Lock UI after 20 inactive minutes. Audit privileged actions. MFA is required before enabling L4.

`has_role` is intentionally `SECURITY DEFINER` and executable only by `authenticated`; this avoids recursive RLS on `user_roles`. Its fixed empty search path and fully-qualified objects reduce function-hijacking risk. Audit triggers are not directly executable by API roles.

The Owner brief reads through one fixed `SECURITY DEFINER` aggregation function with an empty search path and a mandatory Owner/Super Admin check before any query. It exposes bounded counts, OMR totals and up to eight receivables/projects; it accepts no table, column, filter or SQL input and performs no writes.

Commercial lifecycle changes are serialized by row locks inside `SECURITY DEFINER` functions with an empty search path. The finance-document guard refuses direct paid-balance mutation, quote payment, stage skipping, finalized-document edits, overpayment, and reasonless reversal. Line totals, discount and document-level tax are calculated in PostgreSQL from bounded validated inputs. Issuing freezes an immutable seller/customer/line/total/date/terms snapshot; a later company-profile edit cannot rewrite an old quote or invoice. Legal and bank details are Owner/Super Admin-only, and their general audit receipt records only the update time rather than copying sensitive values. Payment receipts contain status and business-case identifiers in the general audit log, while financial amounts remain in the Owner-only ledger. Recording a receipt never executes a payment; enabling a payment rail still requires MFA-backed L4 approval and a separate threat review.

WhatsApp administrator memory is opt-in per linked account. Raw inbound/outbound text remains in the existing access-controlled message ledgers; the style profile contains aggregate signals only and is never shared between administrators. Explicit durable memories use the authenticated administrator's user scope. The webhook rejects unknown/disabled phone bindings, rechecks active roles on every request, redacts credential-shaped text, bounds conversation history, and treats history/context as untrusted data. Governed agents and conversational replies have different enforcement paths. Conversational quality scores flag contract breaches for monitoring; a passing score is not a proof of truthfulness or a replacement for tool authorization.

QR groups are deny-by-default: discovery creates a disabled group and an Owner explicitly enables participation. Mention/ambient response, unlinked-member chat and text/voice settings are enforced by the runtime. A linked sender's actual account controls tool authority; an unlinked group member can receive only permitted public conversation. The group's display name never grants authority. A disabled group stops before message/job persistence and queued automatic work is cancelled when disabled.

The WhatsApp assistant classifies free wording into a closed intent catalogue, and the model never executes anything: every routed field is re-validated in code, and both the router and the executor independently refuse a recipient or link that does not appear in the person's own message. External sends still require a written confirmation, an approval read from wording rather than an exact phrase must be short, unambiguous and actually pending, and a superseded request is cancelled rather than left approvable. Reply decoding is chosen per job through named profiles in the local adapter; a caller may narrow temperature, top-p, repeat penalty and prediction length within clamped bounds and can reach no other decoding option.

Web access is two read-only tools behind the existing governed catalogue and is disabled until an Owner supplies a provider key. The reader accepts https only, refuses credentials in a URL and non-default ports, resolves the host and rejects the request if any returned address is private, loopback, link-local, carrier-grade NAT or IPv4-mapped, and repeats that check on every redirect hop rather than trusting the first URL. Content type, body size and redirect depth are bounded. Outbound queries are intersected with the words the person wrote, so company context cannot leave with a search. Retrieved page text is wrapped in an explicit untrusted marker, passed as data, and can never produce an action.

Assistant memory keeps its opt-in switches and adds automatic extraction on a message cadence; one-time codes, passwords, card-shaped digit runs and API keys are refused before anything is stored. Semantic recall runs through a scope-bounded `SECURITY DEFINER` function that is executable only by the service role and never reads outside the caller-resolved scope. Thumbs and written corrections are recorded against the reply they judge and are used only to shape recall and measurement; they never modify the assistant's own instructions, which would turn a thumbs-down into an injection vector. Every reply is scored against a deterministic contract covering prompt leakage, credential requests, unbacked action claims, wrong-language answers and repeated openings, and the score travels with the delivered message.

Voice notes and photos are transcribed and described on the local adapter; nothing leaves the machine, and an inbound photo is held in a bounded in-memory cache consumed by the job that answers it rather than written into company storage. PDF generation fails closed when the bundled Arabic font is missing instead of silently falling back to a Latin-only face.



Customer journeys use an Owner-authenticated SECURITY DEFINER RPC with an empty search path, explicit allow checks and one transaction. Link-table RLS is Owner-only; assigned employees see the task/request under existing policies, not the conversation. Table writes are disallowed to ordinary browser roles. The action feed similarly requires an active Owner/Super Admin before reading any record.

Local chat inference has concurrency/time/output bounds and a recovery circuit. Neither its diagnostics nor usage events contain conversation content. No external fallback is enabled by the connected-operations change. Meeting preflight reads provider health/authorization and never creates a Google space or Recall bot. Its transcription flag is configuration evidence only.
