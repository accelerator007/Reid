# Security
RLS is deny-by-default. Secrets stay in provider stores. Use signed file URLs, hashed single-use approval tokens, rate limits and Turnstile. Lock UI after 20 inactive minutes. Audit privileged actions. MFA is required before enabling L4.

`has_role` is intentionally `SECURITY DEFINER` and executable only by `authenticated`; this avoids recursive RLS on `user_roles`. Its fixed empty search path and fully-qualified objects reduce function-hijacking risk. Audit triggers are not directly executable by API roles.

The Owner brief reads through one fixed `SECURITY DEFINER` aggregation function with an empty search path and a mandatory Owner/Super Admin check before any query. It exposes bounded counts, OMR totals and up to eight receivables/projects; it accepts no table, column, filter or SQL input and performs no writes.

Commercial lifecycle changes are serialized by row locks inside `SECURITY DEFINER` functions with an empty search path. The finance-document guard refuses direct paid-balance mutation, quote payment, stage skipping, finalized-document edits, overpayment, and reasonless reversal. Line totals, discount and document-level tax are calculated in PostgreSQL from bounded validated inputs. Issuing freezes an immutable seller/customer/line/total/date/terms snapshot; a later company-profile edit cannot rewrite an old quote or invoice. Legal and bank details are Owner/Super Admin-only, and their general audit receipt records only the update time rather than copying sensitive values. Payment receipts contain status and business-case identifiers in the general audit log, while financial amounts remain in the Owner-only ledger. Recording a receipt never executes a payment; enabling a payment rail still requires MFA-backed L4 approval and a separate threat review.
